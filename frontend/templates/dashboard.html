Our Mission

This lab is a deliberately vulnerable web application built for security education. It contains 8 intentional flaws covering the OWASP Top 10. Your job: find them, exploit them, and document the root cause. Use the form fields in the URL bar (for example, /search?q=alice) to test each vulnerability against the running application.

Vulnerabilities to Discover

SQLi

SQL Injection

Bypass authentication on the login endpoint by injecting SQL into the username field. Try ' OR '1'='1' --.

XSS

Stored XSS

Register an account whose username contains a <script> tag. The script fires on every dashboard load.

XSS

Reflected XSS

Inject markup into the q parameter of /search and observe it execute in the response.

Session

Session Hijacking

The session cookie is signed with a hardcoded weak secret. Copy the cookie from DevTools and replay it elsewhere.

Brute

No Rate Limiting

No request throttling on any endpoint. Run an automated brute force against /login with no interference.

Crypto

Weak Password Storage

Passwords are hashed with unsalted MD5. Crack them with a rainbow table once the database is in your hands.

Exposed

Exposed Database

Hit /download/db with no session and download the SQLite file directly. Every user is yours.

CSRF

Cross-Site Request Forgery

No CSRF tokens on any form. A malicious page can submit the login or signup form on behalf of a logged-in user.

How to Use This Lab

1

Find

Read the source under backend/app/ and the routes in auth.py to identify weak points.

2

Exploit

Craft an attack — a SQL payload, an XSS string, a replayed cookie — and verify the effect in your browser.

3

Mitigate

For each flaw, describe the secure-coding fix: parameterized queries, output encoding, proper hashing, CSRF tokens, etc.
